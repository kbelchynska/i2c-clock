# Модуль 4.4. SPI BME280 (на основі 4.3 I²C годинника)

**ESP32-S3-DevKitM-1** зчитує час з RTC **DS1307** (I²C), температуру, вологість і тиск з **BME280** (SPI)
і показує все на OLED **SSD1306 128×64** (I²C):

```
        15:33:59          ← HH:MM:SS, шрифт ×2
     Sat 14.02.2026       ← EEE DD.MM.YYYY
   T: 23.4°C RH: 45%      ← BME280
      P: 1013 hPa
```

Усі драйвери написані на `Wire` / `SPI` без сторонніх бібліотек.

## Підключення

I²C:

| Модуль         | SDA   | SCL   | VCC  | GND |
|----------------|-------|-------|------|-----|
| ESP32-S3       | GPIO8 | GPIO9 | —    | GND |
| SSD1306 (0x3C) | SDA   | SCL   | 3.3V | GND |
| DS1307 (0x68)  | SDA   | SCL   | 5V   | GND |

SPI (BME280, 3.3 В):

| BME280     | ESP32-S3         |
|------------|------------------|
| VCC        | 3.3V             |
| GND        | GND              |
| SCL (SCK)  | GPIO12           |
| SDA (SDI)  | GPIO11 (MOSI)    |
| SDO        | GPIO13 (MISO)    |
| CSB        | GPIO10 (CS)      |

Для SPI потрібен 6-піновий модуль BME280 (з виведеними CSB і SDO). Чип переходить у режим SPI,
коли бачить низький рівень на CSB, і залишається в ньому до вимкнення живлення.

DS1307 працює лише від 4.5–5.5 В (при 3.3 В він переходить на батарею і не відповідає по I²C).
Високий рівень I²C для нього ≥ 2.2 В, тому шина на 3.3 В підходить. Якщо на RTC-модулі
є підтяжки SDA/SCL до його VCC (5 В), їх слід прибрати — піни ESP32 не толерантні до 5 В.

## Як працює

1. `initI2C()` — `Wire` на 100 кГц.
2. `initDisplay()` — послідовність ініціалізації SSD1306 (0xAE … 0xAF) одним кадром з control byte `0x00`.
3. `initRtc()` — якщо біт CH (осцилятор зупинено) встановлений, записується час компіляції.
4. `initBme()` — SPI 1 МГц, mode 0. Перевірка `chip_id` (0xD0 = 0x60), soft reset (0xE0 ← 0xB6),
   читання калібрувальних коефіцієнтів (0x88–0xA1, 0xE1–0xE7), налаштування:
   `ctrl_hum` = ×1, `config` = t_standby 125 мс без фільтра, `ctrl_meas` = T×1, P×1, **normal mode** —
   датчик сам міряє безперервно, MCU лише читає готовий результат.
5. `readTime()` — 7 регістрів DS1307 (0x00–0x06), BCD → двійкові.
6. `readClimate()` — одне burst-читання 0xF7–0xFE (P, T, H з одного циклу), компенсація цілочисельними
   формулами з даташиту Bosch: T у 0.01 °C, P у Па (Q24.8) → гПа, H у %RH (Q22.10).
   Якщо датчик не відповідає — на екрані `--`, а ініціалізація повторюється при наступному опитуванні.
7. `updateDisplay()` — малювання в буфер 1024 байти, потім передача в GDDRAM (`0x21`/`0x22` + дані з `0x40`).

Основний цикл без `delay()` — два незалежні таймери на `millis()`:

- RTC опитується кожні **200 мс**;
- BME280 — кожні **500 мс** (вимога — не рідше 1 разу на секунду).

Після кожного опитування формується вміст екрана; якщо він змінився — екран перемальовується, а той самий
вміст дублюється в лог через `ESP_LOGI` (рівень вмикається `-DCORE_DEBUG_LEVEL=3` у `platformio.ini`):

```
[  5123][I][main.cpp:184] logScreen(): [clock] 15:33:59 Sat 14.02.2026 | T: 23.4°C RH: 45% | P: 1013 hPa
```

Час можна виставити з Serial Monitor (115200): `2026-02-14 15:33:59`. День тижня рахується автоматично.

## Структура

- [src/main.cpp](src/main.cpp) — ініціалізація, таймери опитування, формування екрана і логування.
- [src/bme280.cpp](src/bme280.cpp) — драйвер BME280 по SPI (регістри, калібрування, компенсація).
- [src/ssd1306.cpp](src/ssd1306.cpp) — драйвер дисплея, текст у буфер.
- [src/ds1307.cpp](src/ds1307.cpp) — драйвер RTC.
- [src/font5x7.h](src/font5x7.h) — шрифт 5×7 (цифри, `: . - %`, `°` та потрібні літери).
